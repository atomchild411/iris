# SGI O2 (IP32)

The O2 is SGI's unified-memory workstation: CRIME (the memory controller and
rendering engine), MACE (the I/O chip: PCI, Ethernet, serial ports, PS/2,
audio, the clocks) and GBE (the display engine, which scans the frame buffer
out of main memory). IRIS emulates it with an R10000 or an R5000, chosen at run
time like the other machines.

It runs IRIX 6.5 (tested with 6.5.22) to the desktop, with networking, audio,
SCSI disks and CD-ROMs, X and OpenGL through the CRIME rendering engine, and
NetBSD 11 to multi-user and X (its `crime` driver, accelerated). OpenBSD 6.9
boots but is not maintained. Linux is not usable yet.

The O2 does not run in iris-gui yet; start it from the `iris` command line.

## Configure the machine

The O2 has its own `[o2]` section; the Indy and Indigo2 top-level keys
(`prom`, `nvram`, `banks`, `[scsi.N]`) do not apply to it.

```toml
[machine]
profile = "o2_ip32"
cpu = "r10000"              # or "r5000"

[o2]
prom = "ip32prom.rev4.18.bin"
flash = "flash.bin"
ram_mb = 1024
serial_port = 2291
serial_log = "serial.log"
control_port = 2293
disks = [ { id = 1, path = "irix6522.raw" } ]
forwards = [ { proto = "tcp", host_port = 2292, guest_port = 22 } ]
```

Paths are relative to the directory iris runs in. Every key is listed in
[FEATURES.md](../FEATURES.md#o2).

The PROM image is not built in: supply the O2 PROM (4.18 is the last
release) as `prom`. The O2 has no NVRAM chip; the PROM keeps its environment
(`setenv`) in flash. With `flash = "FILE"`, IRIS starts from FILE when it
exists and saves the flash back there whenever the guest writes it, so
settings survive a restart. The PROM image itself is never written.

## CPU, memory and clock

- **R10000.** The PROM sizes memory with its stack in the data cache, so the
  full cache model runs through POST; once an operating system's kernel runs,
  IRIS switches to the faster shadow cache model that IP28 uses. A reboot
  through the PROM switches back.
- **R5000.** The full cache model throughout. Linux supports only R5000-class
  O2s.
- `cpu_mhz` (default 180) sets the clock the PROM measures and reports; CP0
  Count runs at half of it. R10000 O2s shipped at 175 and 195 MHz.
- `ram_mb` fits memory the usual way, largest DIMM kits first, up to 1024 MB.
  `dimms = [128, 128]` gives the kit in each DIMM pair instead.

## Disks and CD-ROMs

`disks` lists SCSI devices on the two Adaptec 7880 controllers: `id`, `path`,
`cdrom = true` for a CD-ROM image, and `bus` 0 (internal, the default) or 1
(external). IRIX expects the system disk at id 1 on bus 0. Disk images are
written in place, as on the other machines.

## Console, keyboard and mouse

With `graphics = true` (the default) the PROM and IRIX use the graphics
console with a PS/2 keyboard, and `mouse` (default on) adds a PS/2 mouse.
With `graphics = false` the console is serial port 1.

`serial_port` serves the first serial port on TCP 127.0.0.1 (`telnet
127.0.0.1 PORT`); `serial_log` copies everything it sends to a file.

## Networking

The O2's Ethernet is on IRIS's NAT gateway, as on the other machines: the
guest gets 192.168.0.2 by DHCP, with the gateway and DNS at 192.168.0.1.
`forwards` maps host ports to guest ports (same fields as `[[port_forward]]`).
`net = false` leaves the Ethernet unplugged.

For a PROM network boot, set `[network] tftp_dir = "DIR"` and boot from the
PROM's command monitor with `boot -f bootp():FILE`, which loads FILE from DIR.

## Scripting and inspection

The monitor (`monitor_port`) has the O2's device commands (`crime`, `gbe`,
`re`, `mec`, `pci`, `audio`, ...) and an `o2 <command>` family; see
[debug.md](../debug.md#sgi-o2-ip32). `control_port` serves the same `o2`
commands on their own TCP port, one command per line, for scripts: screen
shots, typed text and keys, mouse motion and clicks, memory reads.

## Known limitations

- No machine snapshots, and no iris-gui support yet.
- The PROM cannot load a very large program from disk (it fails on a 16 MB
  kernel); boot such a file over TFTP instead.
- PCI's byte-swapped view of memory is not modelled; every driver tested uses
  address order in both views.
- Reading pixels back from the rendering engine (`glReadPixels`) returns
  zeros.
